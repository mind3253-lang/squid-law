# 경쟁 법률 셀프서비스 벤치마크 — 개발 로직 검토 항목 (2026-10-18)

상태: **검토 대기 / 기능 미구현**. 경쟁사 공개 설명에서 얻은 아이디어이며 실제 품질·성능은 검증하지 않음. 기존 기능을 덮어쓰거나 과금·배포 정책을 변경하지 않는다.

## 우선 검토 1: 주장–요건–사실–증거 추적성
- 사건별 쟁점 ID, 법률요건 ID, 사실 주장 ID, 증거 ID, 출처(파일/페이지/문단), 입증 방향(지지/반박/불명), 신뢰도·검토 상태를 연결.
- 보고서 기존 3파트(쟁점표 1장, 분석, 결과)는 유지. 본문은 핵심 주장, 출처는 각주로 정확히 연결.
- 증거가 없거나 법률요건 충족 여부가 불명확하면 '미확인' 표기. 없는 증거/판례/페이지 생성 금지.
- 신규 증거 재분석은 기존 구조 전체 재처리 대신 영향받은 쟁점·연결만 갱신. 사건 간 채권 귀속 및 동일 금원 중복 계산 경고.
- 검증: 다중 사건, 같은 증거 재사용, 증거 충돌, 페이지 누락, 중복 문서, 338쪽 자료에서 정확성·속도 확인.

## 우선 검토 2: 사건 절차·기한·법원 식별
- 사건 식별키는 법원 식별자 + 사건번호 + 심급 + 당사자 역할을 포함. 법원명/지원/시법원 구별, 이송·항소 전후 사건 연결.
- 사건명, 원고·피고, 청구취지, 진행 상태, 기일·제출기한, 명령 근거 파일 및 확인 여부를 구조화.
- 기한 추출은 '법원 문서에 명시된 날짜'와 '시스템 계산·추정'을 구분하고 사용자 검토 후 확정. 기한 누락/충돌/기일 임박 표시.
- 서면 제출 전 체크리스트: 법원명, 사건번호, 당사자, 첨부증거, 기한. 실제 접수·제출 여부는 확인되지 않으면 완료로 표시하지 않음.
- 개인정보 및 사건별 접근 권한 고려. 알림·자동제출은 별도 승인 전 활성화 금지.

## 검토 3: 병렬 AI 분석
- Astraea Pro-Se의 공개 설명을 아이디어로 삼아, 역할별 분석(원고 주장/피고 주장/모순/증거 인용) 후 충돌 해소 단계 설계 가능성 검토.
- 비용, 처리시간, 정확도 비교 실험 후 채택. 기존 분석 엔진과 A/B 비교; 338쪽 목표 120초 내외는 성능 목표이지 달성 사실 아님.

## 검토 4: 결제 전 미리보기
- Answered식 미리보기 아이디어: 개인정보 노출 없이 보고서 구조/샘플 또는 제한된 미리보기 제공 가능성 검토.
- 원문 증거·민감정보 노출, 무단 재배포, 결제 전후 품질 차이, 악용 방지 확인.

## 검토 5: 과금 단위
- Courtroom5의 크레딧 모델과 현재 사용량 원장·증분 재분석 과금을 비교.
- API 실측 원가 기반 가격 설정. 최소 마진 목표와 사용자에게 이해 쉬운 청구단위 검토. 기존 결제·포인트 변경 금지.

## 실행 원칙
1. 기존 SQUIDLAW 작업 목록과 중복 여부 조사 후 각 항목을 기존 작업 ID에 연결.
2. 제품 방향을 임의로 바꾸지 않고 '검토→설계→테스트→승인→구현' 순서 준수.
3. 이 문서는 검토 항목을 코드 저장소에 기록한 것이며 기능 구현·배포·검증 완료를 의미하지 않음.
