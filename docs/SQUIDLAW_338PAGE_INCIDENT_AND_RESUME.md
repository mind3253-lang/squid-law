# SQUIDLAW — 338페이지 실운영 장애 및 중단 후 재개 명령 (2026-10-12)

## 실사용자 보고 — 사실
- SQUIDLAW(squidlaw.co.kr) 고객 법률 분석에서 문서 1개, 총 338페이지 처리.
- 원문 검증 UI: 100% (338/338페이지), 약 70분 소요.
- 표시 단계: `text_review_finalize_checkpoint`; UI는 '분석 처리 중' 상태 유지.
- 법률 분석 보고서 열기 시 '법률 분석 보고서가 아직 생성되지 않았습니다'.
- UI 오류: `Unexpected token 'A', "A server e"... is not valid JSON`.
- 화면에 '서버 보관 문서 1개 · 저장된 대화 2개' 표시.
- **338/338은 원문 검증 완료율일 뿐 법률 분석/보고서 완료율이 아니다.** UI가 이를 혼동하게 해서는 안 된다.
- 해당 고객 자료, 작업 상태, 체크포인트, 부분 결과는 절대 삭제/초기화하지 말 것.

## 코드 조사에서 확인된 사실
- `api/customer-analysis-worker.js`에서 `text_review_finalize_checkpoint`를 반환하는 분기 확인.
- 해당 분기는 `finalizeOffset`, `finalizeUnitCount`, `finalizePartDigests`를 checkpoint에 보관하고 `finalize-parts/*.json`에 부분 결과를 저장한 뒤 `status:'retry'`를 반환함.
- 다음 단계에서 `FINALIZATION_DIGEST_COUNT_MISMATCH`, `FINALIZATION_PART_MISSING` 등 검증 오류 가능 경로가 있음. **실제 발생 원인은 아직 로그로 확인되지 않음.**
- 오류 문자열 `Unexpected token 'A'...`는 클라이언트가 JSON이 아닌 서버 응답을 JSON으로 파싱했음을 시사. 실제 HTTP 상태코드/응답 본문/로그 확인 전까지 원인 확정 금지.
- 이전의 소스/출처 정합성 및 OCR 관련 커밋이 있어도 이번 338페이지 운영 E2E 성공 증거가 아니다.

## 최상위 복구 명령
1. GitHub `mind3253-lang/squid-law` 최신 main과 Vercel `squid-law` 최신 배포/함수 로그를 조회한다.
2. 현재 사용자의 기존 338페이지 분석 job을 **읽기 전용**으로 조사한다. 개인식별정보·문서내용·키는 로그/대화에 노출하지 않는다. jobId를 모르거나 API 권한이 없으면 확인 가능한 서버 코드와 안전한 재현 테스트부터 수행한다.
3. `api/customer-analysis-worker.js`의 finalize 분기, checkpoint 저장·조회, `finalize-parts` 일관성, retry → 다음 실행 스케줄, worker 크론 인증, 런타임 제한, 보고서 생성/저장/열기 API까지 전 경로를 추적한다.
4. `Unexpected token 'A'`의 **발생 요청 URL, 상태코드, Content-Type, 응답 본문 앞부분**을 서버 로그 또는 안전한 재현으로 확보한다. 클라이언트가 비JSON 응답을 그대로 JSON.parse하지 않도록 수정하고 사용자에게 적절한 오류/재시도 메시지를 제공한다. 원인을 숨기지 않는다.
5. 338페이지가 이미 검증됐으면 **기존 체크포인트부터 재개**한다. 처음부터 70분 재처리하지 않는다. 중복 실행/중복 비용 방지.
6. finalize 결과 집계 → 법률 분석 → 보고서 저장 → 보고서 열기까지 실제 흐름을 연결·검증한다. 중간 실패 시 마지막 성공 단계로 재개한다.
7. 진행률을 '원문 검증 100%'와 '전체 법률 분석 진행 단계/보고서 준비'로 명확히 구분한다. 100%를 최종 완료처럼 표시하지 않는다.
8. 성능 병목을 측정하고 338페이지 70분을 개선한다. 증거 누락/검증 생략으로 속도만 올리지 않는다. 작업당 소요시간, 재시도, 모델 비용을 기록한다.
9. 기존 338페이지 데이터에 영향 없는 fixture/테스트로 회귀 검사 후 운영 환경에서 E2E 검증한다. 성공 확인 전 완료라고 주장하지 않는다.
10. 중단/강제 리턴 시 아래 상태를 갱신하고 다음 방에서 **검증 완료한 작업만 제외**하여 계속한다.
