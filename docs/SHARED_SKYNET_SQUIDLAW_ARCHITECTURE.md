# SKYNET · SQUIDLAW 개발 구조 — 사용자 확정 원칙 (2026-10-18)

> **최상위 고정 설계.** 방 변경·작업 재개 시 반드시 읽는다. 이 문서는 실행 로직이 아니며 스카이넷의 응답 경로에 추가 분석 단계를 만들지 않는다.

## 제품 역할 (기존 '스카이넷에 법률 기능 통합' 계획 폐기)
- **SKYNET:** 사용자의 장기기억·대화·문서를 정확히 저장하고 빠르게 검색·연결·응답하는 경량 기억 시스템. 질문마다 전체 기억을 재분석하거나 법률 엔진·무거운 계산을 상시 실행하지 않는다. 검색 우선, 복잡한 처리는 명시적으로 필요할 때만 비동기/별도 실행.
- **SQUIDLAW:** 법률 사건 자료, 법률 추론(GPT API), 판례·증거 검토, 소장·준비서면 및 보고서 담당. 법률 전문 기능을 SKYNET에 복제하지 않는다.
- **두 제품 연결:** SQUIDLAW에서 완료한 분석 결과물을 사용자가 SKYNET 기억에 저장·조회할 수 있도록 한다. 자동 전달은 별도 기능으로 구현·검증하기 전까지 완료라고 주장하지 않는다.
- **언어·감정·대화 패턴:** SKYNET 전용. 법률 사건 해석 규칙과 혼합하지 않는다.

## 공통 기능만 공유
- 문서·대화 대용량 분할 처리, 원문 SHA-256/페이지 무결성, 페이지·문서 경계와 누락 검증, 체크포인트·재개, 출처·원문 위치 참조, 작업 상태·오류 분류, 공통 회귀 검증.
- **공통 기능의 재사용은 실제 공유 모듈을 import/re-export하는 방식**으로 한다. 제품별 같은 코드를 복사해 각각 유지보수하지 않는다.
- 기존 연결: `lib/shared-source-integrity.mjs`; `lib/page-digests.mjs`, `lib/batch-integrity.mjs`, `lib/skynet-upload-digest.mjs`, `lib/customer-source-ingest-audit.mjs`에서 공유. 공유 범위 이외의 기능이 자동 동기화된다고 주장하지 않는다.
- 공유 코드 변경 시 **SKYNET 및 SQUIDLAW 테스트를 모두 확인**한다. 기존 실패는 별도 추적하고 새 회귀를 방치하지 않는다.
- 공통 엔진이 SKYNET 일반 채팅의 매 응답에 개입하지 않도록 한다. 파일 수집/검증/백그라운드 처리에서만 호출.

## 성능·안전 불변식
1. 기억량 증가에 비례하여 매 질문의 전체 스캔·재분석을 늘리지 않는다. 색인 검색 후 필요한 범위만 읽는다.
2. 원문과 기억은 보존한다. 출처·누락·해시 검증을 생략해 속도를 높이지 않는다.
3. 고비용 처리와 무거운 문서 분석은 별도 작업으로 실행하고 체크포인트를 유지한다.
4. 고객/관리자 자료 격리와 접근 권한을 유지한다. SKYNET으로 고객의 법률자료가 무단 유입되지 않는다.
5. 속도 목표는 실제 검색 지연·자료량·회귀 테스트로 측정하며, 검증 없이 성능 개선 완료라고 보고하지 않는다.
