# SKYNET — 지속 개발 기준서 (2026-10-12)

> 이 문서는 새 채팅방/새 작업 세션에서 가장 먼저 읽어야 하는 프로젝트의 지속적 작업 기준이다. 사용자에게 이미 확정한 설계를 다시 묻지 말고, GitHub 현재 코드와 배포를 먼저 확인한다. 완료 여부는 실제 코드/테스트/운영 검증으로 구분한다.

## 확정된 제품 정의
- SKYNET(스카이넷)은 독립 웹사이트가 아니다. SQUIDLAW(스키드로우, squidlaw.co.kr) 내부의 **관리자 전용 AI 동료이자 영구 작업 공간**이다.
- GitHub: `mind3253-lang/squid-law` 기본 브랜치 `main`; Vercel 프로젝트 `squid-law`.
- **기능 선별 축소판 금지.** OpenAI API에서 실제 제공되는 모델·도구·파일/검색/멀티모달/실행 기능을 최대한 통합하고, 불필요한 기능을 제거하는 **포괄적 통합 방식**. ChatGPT 완제품 전체를 API 한 번으로 복제할 수 있다고 가정하지 않는다. 미제공 제품 기능은 SQUIDLAW 내부 실행/기억/권한 레이어로 구현한다.
- 기존 OPENAI_API_KEY, ADMIN_PASSWORD, BLOB_READ_WRITE_TOKEN을 재활용한다. SKYNET_MODEL 환경변수는 선택 사항. 별도 사이트·별도 결제·새 가입을 요구하지 않는다. 환경변수 값/실제 권한은 운영 테스트 전까지 검증됐다고 말하지 않는다.
- SKYNET 말투는 기존 사용자와 오정/오징어의 자연스러운 한국어 반말. 고객센터식/교과서식 챗봇 말투, 불필요한 공감·사과·훈계·장황한 나열·반복 질문 금지. 간단한 질문에는 짧게, 복잡한 작업은 충분히 수행. 사용자의 최종 판단권 존중.
- **자동 기억 저장**: 정해진 대화량/주기에 도달하면 사용자에게 매번 허락받지 않고 자동 저장. 관리자인증은 외부 무단 접근 차단용이며 자동저장 동작을 방해하거나 매번 비밀번호를 묻는 동의 절차가 아니다. 자동저장 임계값은 UI/코드 확인 후 기존 합의를 유지한다.
- 대화와 파일, 개발결정, TODO, 작업로그, 오류/테스트결과, 소스커밋, 배포 상태를 장기 보존. 사건별 자료 혼동 방지, 원문 출처 추적, 파일 재검색/재분석 가능해야 한다.
- 장시간 개발은 10초/커밋마다 대화를 끊고 보고하는 방식 금지. 작업 상태를 서버 측에 영속 저장하고, 재시도·재개·취소·진행 조회가 가능한 **지속 실행 작업**으로 설계. 완료 또는 실제로 막힌 지점에서만 사용자에게 보고. HTTP 응답 대기시간을 무한대로 만드는 방식으로 해결하지 않는다.
- GitHub 코드 조회/수정/커밋, Vercel 배포·로그 확인, 파일 읽기·생성·분석, 웹 검색, 테스트/오류수정 반복 등 가능한 도구를 AI가 명시적 권한 범위에서 사용하도록 한다. 비밀정보 노출 금지, 고객 데이터 파괴 금지, 프로덕션 영향 변경은 보호장치 적용.
- 테스트 통과와 운영 검증을 혼동하지 않는다. mock, 배포 READY, 코드 존재만으로 실서비스 작동을 주장하지 않는다.

## 2026-10-12 확인된 현재 상태
- `api/skynet-chat.js`: OpenAI chat/completions 호출 + 프로필/검색기억 컨텍스트. 기본 모델 문자열 `gpt-6.1-sol`(실제 API 호출 성공 미확인). 메시지 24개, 기억 20개, 검색 최대 160개 파일, 컨텍스트 32k 문자. 답변 최대 5000 토큰, 요청 90초로 조정. 이는 장시간 작업 실행기가 아님.
- `api/skynet-memory.js`: Blob 대화 자동 저장/검색 및 DB 저장. 2026-10-12 관리자 인증 추가. 클라이언트 자동저장 조건/인증 헤더 호환성은 실서비스 검증 필요.
- `api/skynet-archive.js`: 업로드 조각 보관/조회. 2026-10-12 관리자 인증 추가. 클라이언트 업로드 인증 호환성 확인 필요.
- `api/skynet-import.js`: ChatGPT 대화 ZIP/JSON 가져오기 및 검색 인덱싱. 관리자 인증 있음.
- `api/skynet-document.js`: PDF, DOCX, XLSX, 이미지 등 자료 처리. PDF 시각 검토/원문 검증까지 완성됐다고 가정하지 않는다.
- `api/skynet-search-index.js`, `api/skynet-retrieval.js`, `api/skynet-timeline.js`, `api/skynet-profile.js` 존재.
- 스카이넷 대화 API에 실제 도구 호출·GitHub/Vercel 실행 루프·영속 작업큐·비용 계측 기능이 아직 확인되지 않았다.
- Vercel 최신 이전 프로덕션 배포 READY `8cdc55f`; 2026-10-12 보안/말투 개선 커밋 `5630a3a`, `b53b235`, `67f2c8d` 이후 배포는 당시 진행 중. Vercel 환경변수 API 조회는 403으로 실패. 사용자 화면상 SKYNET_MODEL 미등록, 다른 3개는 사용자가 확인 중.

## 반드시 이어서 할 작업 (우선순위)
1. 최신 main/배포 및 SKYNET UI의 memory/archive 호출부 확인. 새 인증 추가 후 자동저장·업로드가 정상 작동하는지 검증/수정. 기존 자료 절대 삭제하지 말 것.
2. 자동저장 임계값·영속 대화 재로딩·새 방 재개·검색 정확성, 기억 출처/프로젝트 격리 테스트.
3. OpenAI API 실호출: 모델 지원 여부, 응답 오류, 실제 사용량, 비용, 멀티모달 확인. 지원하지 않는 모델명은 실제 확인 후 교체.
4. 가능한 OpenAI 도구 기능 전체를 inventory 작성하고 SKYNET에 도구 레지스트리/권한/실행 경로를 연결. 임의로 소수 기능만 고르는 접근 금지.
5. 지속 작업 상태머신(queued/running/blocked/completed/failed/cancelled), 영속 체크포인트/작업로그/재개, 안전한 도구 실행 및 GitHub/Vercel 통합. 서버리스 단일 요청 90초 제한에 의존하지 말 것.
6. API 비용·토큰 기록, 보안/권한 테스트, 실제 운영 E2E 시험. 모든 변경은 테스트/오류 수정/재검증까지 반복.
