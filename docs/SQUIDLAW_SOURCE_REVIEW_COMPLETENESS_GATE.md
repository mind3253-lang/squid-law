# SQUIDLAW 원문 실검토율·근거대조 게이트 — 2026-10-13

## 문제와 우선순위
- 146쪽 문서를 6초 만에 답한 것은 전수 증거 검토가 아님. 원문 전송/해시 일치와 쟁점별 이해·검토는 별개임.
- 정확성 우선: 추출 → 모델에 전달 → 페이지/파트별 검토 기록 → 원본 인용 일치 → 쟁점별 상충증거 대조 → 독립 의미 검증 → 완료. **어느 하나도 전수 이해를 단독 증명하지 않음.**
- 146쪽/120초는 시연 목표일 뿐 실측치 아님. 기존 338쪽 약 70분 사례의 실제 처리량·비용·지연을 측정한 뒤 목표 조정.

## 구현 (main)
1. `lib/legal-source-read-audit.mjs`: 원문 파트마다 documentId/page/part/hash/원문 인용/개별 내용 요약을 받아 **누락·중복·허위 인용·빈 일반론**이면 게이트 실패. 부분 누락 시 검토율을 100%로 표기하지 않음.
2. `lib/gpt-legal-expert.mjs`, `lib/gpt-legal-orchestrator.mjs`: 첫 쟁점 검토 패스(`claims_and_rebuttals`)의 모든 원문 파트에 검토 영수증 요구, 서버에서 인용과 원본 일치 감사. 누락 시 해당 작업 재시도/실패 기록.
3. `lib/legal-customer-report.mjs`: 검토 파트·전체 파트, 검토 페이지·전체 페이지, 검토 방식 기록. 한 페이지가 여러 파트일 때 **모든 파트**가 처리되어야 그 페이지 검토 완료.
4. `lib/analysis-completion-reconciliation.mjs`, `lib/analysis-stage-gates.mjs`: `sourceReadReview` 필수 완료 게이트 추가; 전체 원문 인덱스와 검토 파트 수 일치하지 않으면 최종 보고서 `reviewed` 금지.
5. `api/customer-analysis-worker.js`: 신규 검토 결과를 `-read-receipts-v1` 캐시에 저장해 기존 불변 캐시 보존. 기존 검토 영수증 없는 캐시는 자동 완료 처리하지 않음. 오류 코드 `SOURCE_READ_REVIEW_FAILED`.
6. `tests/legal-source-read-audit.test.mjs`: 146개 원문 파트의 완전성, 누락, 중복, 허위 인용, 허위 빈 페이지, 새 완료 게이트 회귀 테스트. 테스트/운영 수용 여부는 별도 확인 필요.

## 아직 끝나지 않은 정확성 작업 (다음 개발 우선순위)
- **의미 검증**: 원문 인용+요약이 존재한다고 해서 GPT가 실제로 문서 전부를 깊이 이해했다는 뜻은 아님. 고위험 쟁점은 반대증거 검색/계약서 원문-기술적 작업-사후 대화 시점까지 연결한 **이슈별 양쪽 증거표**를 만들고 독립 검증할 것.
- **분석 품질 지표**: 문서 원문 확보율 / 모델에 전달된 비율 / 원문 근거 검토 파트율 / 쟁점 상충증거 대조율 / 미확인 핵심 증거 수를 분리 표시할 것.
- **기존 체크포인트 이전**: 신규 영수증 도입 전에 생성된 구형 법률 분석 윈도우는 증거 기록이 부족하여 새 완료 게이트에서 차단됨. 이전 완료 구간에 대한 선택적 재검토 백필 경로를 만들어야 하며 원본·체크포인트 데이터 삭제 금지.
- **속도 최적화**: 146쪽, 338쪽 테스트 데이터에서 단계별 실제 지연·비용·정확성 기록 후 읽기 영수증 배치 크기, 독립 감사 범위, 모델 병렬화 최적화. 검증 없이 120초·20초 달성 표시 금지.
