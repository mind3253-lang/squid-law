# SQUIDLAW 최상위 설계: 공격적 법률 분석 엔진 (2026-10-17)

## 1. 목적과 제품 정체성
**스키드로우는 원고 또는 피고로 지정된 의뢰인의 입장에서 최대한 유리한 전략을 찾아내는 '공격적 법률 분석' 시스템이다.** 상대방 주장을 수동적으로 반박하는 데 그치지 않고, 상대방이 답변·입증해야 할 쟁점을 선제적으로 발굴한다. 변호사가 고객에게 새로운 전략과 증거 확보 방향을 제시할 수 있어야 한다. 공격적은 모욕·허위·과장·근거 없는 단정이 아니라 **적극적 쟁점 발굴, 선제적 청구·반대청구 검토, 증거 중심 압박, 주도적 서면 구성**을 뜻한다.

## 2. 분석 기본값과 역할 고정
- 사건 생성 시 의뢰인 지위(원고/피고), 청구 유형, 소송 단계, 목표를 입력·저장한다. 선택된 역할은 업로드·분할·분석·검증·보고서·대화 후속 분석 전 과정에서 유지한다.
- 원고: 청구원인·요건사실·손해액·입증을 강화하고, 피고의 항변 허점과 추가 청구·보전·절차 전략을 적극 탐색한다.
- 피고: 원고 청구의 요건·인과관계·금액·증거 약점을 찾되 거기서 멈추지 않고 반소·상계·동시이행·부당이득·손해배상·비용·절차적 대응 등 적법한 역공 옵션을 적극 탐색한다.
- 사용자 진술은 탐색의 출발점이지 자동 확정 사실이 아니다. 사건 기록과 증거를 교차 확인하고 불리한 사실도 숨기지 않는다.

## 3. 이중 엔진: 공격적 발굴 + 방어·검증 결합
A. **공격적 탐색(검사식 발굴)**: 상대방 주장 내부 모순, 이전 서면·사건 간 진술 변경, 누락·미이행, 미지급·정산, 증거 공백, 반대청구·상계, 입증책임, 소멸시효, 절차상 문제, 보전처분의 필요성·상당성, 증거신청 기회를 폭넓게 후보화한다. 최초부터 판사식 보수적 결론으로 후보를 제거하지 않는다.
B. **방어형 검토**: 상대방의 예상 반론과 의뢰인에게 불리한 증거를 찾아 대응 논리, 반증, 추가 입증 계획을 작성한다.
C. **증거·법리 검증(판사식 검증)**: 후보별 사실·추정·미확인을 분리하고 원문 파일·페이지·인용 문구·사건번호·시점·법률 요건을 확인한다. 허위 판례·허위 인용 금지. 요건 불충족 시 전략을 삭제만 하지 말고 필요한 증거·대안 경로를 제시한다.
D. **통합 전략**: 검증된 공격 포인트와 방어 논리를 함께 제시하되, 서면은 의뢰인의 가장 강한 주장을 앞세워 읽는 사람이 쟁점을 바로 이해하도록 구성한다.

## 4. 후보별 필수 출력 스키마
- 공격 포인트 명칭 / 의뢰인에게 유리한 이유 / 상대방이 답해야 할 질문
- 법률적 수단(청구, 항변, 반소, 상계, 증거신청, 보전·절차 대응 등) 및 적용 요건
- 근거: 원본 문서명, 정확한 페이지·단락, 원문 인용, 사건·시점, 서로 다른 기록 간 교차근거
- 상태: 확인된 사실 / 당사자 주장 / 합리적 추론 / 미확인 의혹
- 상대방 예상 반박, 의뢰인에게 불리한 자료, 실질적 승패 변수
- 추가 확보할 증거, 확보 방법, 다음 실행 행동, 우선순위
- 근거 부족 시에도 탐색 결과와 부족한 이유를 명시한다. 공격이 없다고 단정하지 않는다.

## 5. 변호사 실무 보고서와 서면
첫 화면 및 최종 보고서에 '핵심 공격적 전략'을 별도 구역으로 제공한다. 단순한 가능성 나열이 아니라 **상대방의 취약점 → 증거 → 실행 가능한 공격 수단 → 예상 반론 → 보강 행동** 순으로 보여준다. 그 다음 방어전략, 주요 위험, 사실확인 과제, 서면 초안을 연결한다.
서면 본문은 핵심 주장·법률효과 중심으로 간결하게, 증거 위치는 정확한 각주·참조로 연결한다. 중립적 재판 전망은 별도 요청·섹션으로 분리하여 의뢰인 측 전략 제시를 희석하지 않는다. 근거 없는 확신·위협적 표현·불필요한 '다만/물론'식 면책 반복은 피하고 실제 법률상 제한만 해당 쟁점에 명시한다.

## 6. 구현 경로 및 검증 기준 (LAW-043, 미완료)
- UI 의뢰인 지위 선택 → DB 영속 저장 → 작업 큐·재개 체크포인트 → 모든 모델 호출 프롬프트 → 중간/최종 보고서 → 사건 대화까지 role 전파 확인.
- 공격 탐색을 독립 분석 단계/구조화 결과로 구현하고 방어 및 법리 검증과 병합한다. 프롬프트 문장 추가만으로 완료 처리하지 않는다.
- PDF 분할 및 사건 간 비교 시 파일·페이지 출처 보존; 원문 누락/충돌 탐지; 근거 없는 전략은 확인 과제로 표시.
- 회귀 테스트: 원고/피고 각각, 공격 증거 충분/부족, 상대방 주장 모순, 장기 미지급·상계 가능성, 관련 사건 간 불일치, 가압류 등 절차적 대응, 불리한 증거, 분석 중단·재개.
- 합격 기준: 각 사례에서 독립 공격 후보와 방어 후보가 나오고, 각 공격 후보에 증거·페이지·실행 행동·예상 반론이 연결되며, 원고/피고 입장이 뒤바뀌지 않고, 허위 사실·판례가 생성되지 않을 것.
- 현황: LAW-043 in_progress. 2026-10-16 공통 프롬프트 일부 수정, 실제 고객 전체 호출 경로 및 운영 검증 미완료. '네 가지 분석 구분'의 정확한 기존 정의는 코드에서 확인한 후 연결하고 임의로 만들지 않는다.

## 7. 제품 메시지
'방어만 하는 법률 AI가 아니라, **의뢰인의 입장에서 공격적 전략을 먼저 발굴하는 법률 분석 엔진**.'
변호사에게는 고객 상담에서 놓친 반대청구·상계·증거 확보·소송 주도권 확보 가능성을 제시하는 실무 도구로 설명한다. 실제 효과는 검증 후에만 성과로 홍보한다.
